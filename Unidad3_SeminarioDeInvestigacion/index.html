Desarrollo preliminar del anteproyecto

Ruta aplicada para avanzar significativamente en la implementación del proyecto, documentar evidencias técnicas e investigativas y preparar una entrega sólida con avances reales.

¿Qué busca esta unidad?

En la Unidad 3 el proyecto deja de ser únicamente una propuesta y comienza a convertirse en una solución tecnológica verificable. El estudiante debe avanzar en el desarrollo de los objetivos específicos, construir evidencias técnicas, validar resultados preliminares y documentar el proceso con rigor investigativo.

Meta de la unidad: lograr un avance significativo del proyecto, idealmente cercano al 80%, integrando desarrollo técnico, evidencia de funcionamiento, validación inicial y documentación académica.

Producto esperado

💻
Avance técnicoPrototipo, sistema, dashboard, modelo, app, arquitectura o módulo funcional.

🧪
Validación inicialPruebas, métricas, encuestas, registros, resultados o evidencias de funcionamiento.

📄
Informe de avanceDocumentación clara del desarrollo, resultados preliminares y dificultades encontradas.

Objetivos de aprendizaje

Al finalizar la Unidad 3, el estudiante deberá demostrar avances concretos en el desarrollo técnico e investigativo del proyecto de Ingeniería de Sistemas.

🚧
Desarrollar componentes del proyectoImplementar módulos, prototipos, modelos, interfaces, bases de datos o tableros según los objetivos definidos.
📌
Gestionar evidenciasOrganizar capturas, repositorios, instrumentos, bases de datos, resultados de pruebas y anexos técnicos.
📊
Validar avancesAplicar métricas, pruebas funcionales, revisión de usuarios o análisis de datos preliminares.
📝
Documentar resultadosRedactar avances del informe con coherencia entre objetivos, metodología, desarrollo y resultados.

Contenido de la unidad

Ruta de desarrollo y validación

Cada apartado conecta el avance técnico con el componente investigativo que debe evidenciarse en el informe del proyecto.

1Plan de desarrollo de objetivos
⌄

El desarrollo del proyecto debe organizarse a partir de los objetivos específicos. Cada objetivo debe convertirse en una acción verificable con productos, evidencias y resultados.

Objetivo específicoAcción técnicaEvidencia esperadaComponente investigativo
Diseñar la arquitecturaConstruir diagramas, modelo de datos y flujo del sistema.Diagramas, modelo entidad-relación, arquitectura.Justificación técnica basada en literatura y requerimientos.
Desarrollar el prototipoProgramar módulos, interfaz, backend o dashboard.Repositorio, capturas, versión funcional.Relación entre desarrollo y problema investigado.
Validar funcionamientoEjecutar pruebas, métricas o evaluación con usuarios.Resultados, tablas, métricas, instrumentos aplicados.Análisis preliminar de datos y discusión de hallazgos.
Clave: no basta con “hacer el sistema”; el estudiante debe demostrar qué objetivo cumple cada avance y qué evidencia lo respalda.
2Desarrollo técnico del proyecto
⌄

El desarrollo técnico depende del tipo de proyecto. Puede incluir software, modelo de IA, dashboard, aplicación móvil, infraestructura de red, dispositivo IoT, base de datos o prototipo funcional.

Tipo de proyectoAvance técnico esperadoEvidencia sugerida
Aplicación web o móvilInterfaces, autenticación, formularios, módulos funcionales, base de datos.Repositorio GitHub, capturas, enlace desplegado, pruebas de usuario.
Modelo de IADataset limpio, entrenamiento, pruebas, ajuste de modelo, métricas.Notebook, matriz de confusión, precision, recall, F1-score.
Dashboard / BIETL, limpieza de datos, indicadores, visualizaciones, filtros.Tablero funcional, dataset, diccionario de datos, análisis.
IoT / hardwarePrototipo, sensores, conexión, captura y almacenamiento de datos.Fotos, registros, código, pruebas de medición, comparación.
Redes / ciberseguridadDiseño, simulación, segmentación, pruebas de tráfico o seguridad.Topología, configuración, métricas, capturas de simulador.
Error frecuente: mostrar capturas sin explicar qué problema resuelven, qué objetivo cumplen o qué resultado evidencian.
3Evidencias técnicas e investigativas
⌄

Las evidencias permiten demostrar avance. Deben organizarse, nombrarse y relacionarse con los objetivos específicos y la metodología.

Evidencia técnica: código, capturas, diagramas, prototipos, enlaces, repositorios, base de datos, métricas, pruebas, logs.
Evidencia investigativa: instrumentos, resultados, análisis, validación, tablas, matriz de categorías, interpretación de datos.
EvidenciaQué demuestraDónde incluirla
Repositorio GitHubDesarrollo progresivo y trazabilidad del código.Anexo técnico / sección de desarrollo.
Capturas del sistemaFuncionamiento de módulos o interfaces.Desarrollo de objetivos.
Instrumento aplicadoRecolección de datos para validación.Metodología / anexos.
Resultados de pruebasDesempeño, aceptación, precisión o cumplimiento funcional.Resultados preliminares.
Recomendación: cada evidencia debe tener título, breve descripción, fecha, objetivo relacionado y análisis mínimo.
4Validación y resultados preliminares
⌄

La validación permite saber si el proyecto responde al problema planteado. No siempre debe ser definitiva, pero sí debe mostrar avances medibles o verificables.

Tipo de validaciónAplicaciónResultado esperado
Prueba funcionalVerifica si un módulo realiza correctamente una tarea.Lista de casos de prueba aprobados o fallidos.
Prueba con usuariosEvalúa percepción, utilidad, facilidad de uso o satisfacción.Encuesta, entrevista, resultados tabulados.
Métricas técnicasEvalúa rendimiento, precisión, tiempo, error, disponibilidad.Indicadores cuantitativos y análisis.
Validación expertaRevisión por docente, profesional o usuario clave.Observaciones, ajustes y mejoras implementadas.
Componente investigativo: los resultados preliminares deben interpretarse, no solo presentarse. El estudiante debe explicar qué significan frente al problema, los objetivos y la metodología.
5Informe de avance y sustentación
⌄

El informe de avance debe mostrar el desarrollo real del proyecto y preparar al estudiante para una sustentación clara, técnica e investigativa.

Sección sugeridaContenido mínimo
Avance por objetivosDescripción de actividades realizadas y porcentaje estimado de avance.
Desarrollo técnicoMódulos, arquitectura, herramientas, código, interfaces o prototipo.
EvidenciasCapturas, enlaces, instrumentos, pruebas, registros, anexos.
Resultados preliminaresDatos obtenidos, métricas, análisis inicial y hallazgos.
Dificultades y ajustesProblemas encontrados, decisiones tomadas y próximos pasos.
Sustentación: se recomienda presentar problema, objetivos, metodología, avance técnico, evidencias, resultados preliminares y plan para culminar el proyecto.

Actividades de aplicación

Ruta práctica para avanzar el proyecto

Estas actividades buscan que el estudiante evidencie avance real del proyecto, no solo preparación documental.

Actividad 1 · Matriz de avance por objetivos

Elabore una matriz donde relacione cada objetivo específico con actividades desarrolladas, evidencia generada, porcentaje de avance y pendientes.

Actividad 2 · Entrega técnica del prototipo o desarrollo

Presente el avance funcional del proyecto: enlace, repositorio, capturas, dashboard, simulación, notebook, prototipo o arquitectura implementada.

Actividad 3 · Validación preliminar

Realice una validación inicial mediante prueba funcional, encuesta, métrica técnica, revisión experta o análisis de datos.

Actividad 4 · Informe y sustentación de avance

Prepare un informe y una presentación corta donde se evidencie el avance del proyecto, los resultados preliminares y la ruta para culminarlo.

Entrega sugerida: informe de avance + evidencias técnicas + validación preliminar + presentación. La meta es aproximarse al 80% de avance real del proyecto.
